Recommended integration order
1. Agree on record fields and shared function interfaces; implement and test
   data loaders because most services depend on reliable records.
2. Build the Task 0 shell and Task 1 vessel loader, then integrate services
   incrementally through the menu.
3. Task 2 and Task 3 share call, manifest and shipment relationships.
4. Task 4 and Task 5 both use shipment or port-call data; they can be developed
   separately once the relevant loaders are stable.
5. Task 6 and Task 7 use incident reports and manifest event codes respectively.
6. Task 8 joins port calls and weather. Task 9 builds and reuses an incident
   index; ensure its cache rules are tested across repeated runs.

Dependency summary
- Task 0 is the shared entry point for all services.
- Tasks 2 and 3 use vessel/call/manifest/shipment relationships.
- Task 4 aggregates shipment records; Task 5 resolves port calls to vessels.
- Task 6 and Task 9 use incident records, with Task 9 also persisting a cache.
- Task 7 uses manifest event_codes; Task 8 joins calls with weather.
- Tasks 1-9 should return control to the Task 0 menu after completion.

See 00-ASSIGNMENT-2-SHARED-REQUIREMENTS.txt for project-wide constraints.
