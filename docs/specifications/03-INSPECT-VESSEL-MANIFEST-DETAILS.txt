HARBORFLOW PORT INTELLIGENCE
TASK 2: INSPECT A VESSEL MANIFEST

Business outcome
Connect a scheduled port call to its vessel and cargo instead of reading files
in isolation.

Goal
For a selected vessel, find its earliest upcoming call on or after a user date,
load that call's manifest by call_id, resolve shipments by shipment_id, and
report the call and cargo totals in manifest order.

Interaction and selection rules
1. Display the registered vessels.
2. Ask for a vessel name. Strip surrounding spaces and match case-insensitively.
3. If the vessel is unknown, print exactly: Vessel not found. Then return to
   the menu.
4. Ask for a reference date in YYYY-MM-DD format. If invalid, print exactly:
   Error - Date must use YYYY-MM-DD.
   Repeat only the date prompt.
5. Filter port calls to the selected vessel and choose the earliest call whose
   arrival date is on or after the reference date.
6. If there is no qualifying call, print exactly: No upcoming port calls found.
   Then return to the menu.
7. If multiple calls share the earliest date, choose the alphabetically
   smallest call_id.

Record-linking steps
- Match port calls to vessel records using vessel_id.
- Find the manifest by comparing its call_id with the selected call_id; do not
  assume a filename equals a business identifier.
- Resolve each manifest shipment_id by comparing it with shipment_id fields in
  shipment records, preserving manifest order.
- If the selected call has no readable valid manifest, print exactly:
  Manifest unavailable.
  Then return to the menu.
- A missing shipment is printed as MISSING RECORD and counted separately. It
  does not invalidate other resolved shipments.

Cargo fields and totals
- Print each resolved shipment's ID, customer, weight_kg and cargo_type in
  manifest order.
- Treat hazardous, temperature_controlled and cargo_type as optional shipment
  fields. Missing boolean flags count as false.
- When cargo_type is displayed but absent, print NOT PROVIDED.
- Count all declared shipment IDs, sum weight only for resolved shipments, and
  count missing shipment records separately.
- Use datetime to present ISO arrival dates as day month year.

Example output
Vessel name: Nordic Relay
Manifest for Nordic Relay | Call HFL-GOT-2048 | 18 October 2026
1. SHP-1042 | Norra MedTech AB | 860.0 kg | REFRIGERATED
2. SHP-1051 | MISSING RECORD
Declared shipments: 2
Resolved weight: 860.00 kg
Missing shipment records: 1

Acceptance checks
[ ] Vessel lookup trims spaces and ignores case.
[ ] Invalid date repeats only the date prompt and uses the exact required error.
[ ] A call on the reference date qualifies; earlier calls do not.
[ ] Equal-date calls use the smallest call_id alphabetically.
[ ] Manifest and shipment lookup compare business identifiers, not filenames.
[ ] Missing shipments remain visible and affect the missing count, not resolved
    weight.
[ ] Missing optional flags count as false; missing cargo_type prints NOT PROVIDED.
[ ] Unknown vessel, no upcoming call and unavailable manifest each print the
    exact message and return to the menu.
