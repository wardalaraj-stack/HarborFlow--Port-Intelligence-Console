2. TASK 5 REQUIREMENT SUMMARY (from the assignment PDF)
================================================================

BUSINESS OUTCOME: Help berth planners review seasonal workload across all
scheduled calls.

Task 5 requirement text:

Ask for a month as an integer from 1 to 12. For non-integer or out-of-range
input, print “Error - Enter a month from 1 to 12.” and repeat only the month
prompt. Read port_calls.csv, resolve each vessel name, and print calls in
that month sorted by arrival_date and then vessel name. Report and skip
invalid dates. If a row refers to an unknown vessel_id, report and skip
that row. If no valid calls match, print “No port calls found.”

Exact example interaction/output from the assignment:
  Month (1-12): 10
  Port calls in October:
  - 02 October 2026 | Baltic Pioneer | CPH | HFL-CPH-2017
  - 18 October 2026 | Nordic Relay | GOT | HFL-GOT-2048
  - 18 October 2026 | Skagerrak Star | AAR | HFL-AAR-2071

Confirmed literal strings and formats:
- Prompt: “Month (1-12): ”
- Invalid input: “Error - Enter a month from 1 to 12.”
- Empty result: “No port calls found.”
- Heading shown for the example month: “Port calls in October:”
- Each shown call: “- {DD Month YYYY} | {vessel name} | {port_code} |
  {call_id}”; the example uses a zero-padded day (“02”), single spaces
  around each vertical bar, and this exact field order.
- Sort order is arrival_date ascending, then vessel name. The example's
  calls on 18 October put Nordic Relay before Skagerrak Star, demonstrating
  the secondary-name ordering for that same-date pair.

The PDF does NOT specify exact diagnostic wording or formatting for an
invalid date row or an unknown vessel_id row. It requires that each such
row be reported and skipped. Use the stable project diagnostic convention
in INTEGRATED-CONTRACT-PLAN.md §3 and this plan's §7; this wording remains
a project convention, not a PDF-mandated string.

3. PROPOSED DESIGN AND MODULE RESPONSIBILITIES
================================================================

Use the shared loading, root-path, and error contracts in
INTEGRATED-CONTRACT-PLAN.md while preserving Task 5's requirements and
exact output strings above. Task-specific helper names below are
descriptive implementation proposals.

data_access.py:
- Reuse the shared `load_port_calls(path) -> LoadResult[PortCall]` loader
  in INTEGRATED-CONTRACT-PLAN.md. It reads CSV rows and retains call_id, vessel_id,
  port_code, and arrival_date. Keep arrival_date as source text here so
  Task 5 can validate each row and report/skip bad dates individually
  rather than letting one bad date invalidate the report. The intended path
  is relative to the project root, e.g. dataset/port_calls.csv, never an
  absolute path tied to one student's computer.
- Reuse the shared vessel `LoadResult` from Task 1 to obtain valid vessel
  records. Build an in-memory vessel_id-to-name lookup from
  those records; Task 5 does not need to print the inventory or duplicate
  vessel-file parsing/validation.
- Keep file reading separate from the date filtering, join, sorting, and
  output formatting. The CSV loader must not silently turn an invalid date
  into a valid one or discard a row that the service is required to report.

operations.py:
- parse_month(text) -> int | raises ValueError: parse and range-check the
  entered month (1 through 12). The caller handles both non-integer text
  and numeric values outside the range through the single exact error
  message, then asks only for the month again. Do not parse a date from the
  user's input; the user supplies a month number only.
- collect_month_calls(month, call_rows, vessels) -> (ordered_calls,
  diagnostics) (proposed): for each CSV row, parse the entire arrival_date
  as a real YYYY-MM-DD calendar date; report and exclude an invalid date.
  Resolve vessel_id against the valid vessel records; report and exclude a
  row whose id has no matching vessel. Include only rows whose parsed
  date.month equals the selected month. Each accepted result needs the
  parsed date, vessel name, port_code, and call_id. Sort accepted results
  by arrival_date ascending, casefolded vessel name, and call_id as the
  final deterministic tiebreaker; the final key is the project policy in
  Section 7 and does not change the PDF's required date/name ordering.
  Keep row-level diagnostics identifiable to the caller and report them
  using the stable project convention; do not silently skip them.
- format_month_heading(month) and format_call_line(call) (or equivalent
  single-purpose formatting): derive the full month name from the selected
  month, and format each call with the observed `DD Month YYYY` date form
  and exact separator spacing from the PDF example. The date text should be
  formatted with a zero-padded day, matching “02 October 2026”; do not
  strip that leading zero.
- Keep operations over already-loaded data free of filesystem I/O where
  practical, so sorting and error branches can be unit-tested with in-memory
  rows and vessel records.

main.py:
- In the selection == 5 branch, ask “Month (1-12): ” until parse_month
  succeeds. On each ValueError, print exactly “Error - Enter a month from
  1 to 12.” and repeat only that prompt; do not print the menu or ask for
  another field inside the retry loop.
- After a valid month, load calls and valid vessel records using the
  shared data-access functions; collect the result and row-level
  diagnostics. Print a diagnostic for each invalid-date and unknown-vessel
  row, skipping each from results. Use the stable diagnostic convention in
  INTEGRATED-CONTRACT-PLAN.md because the PDF does not provide exact wording.
- If no valid calls remain for the selected month, print exactly “No port
  calls found.” Otherwise print the month heading and sorted call lines in
  the format shown in Section 2. Diagnostics must not prevent later valid
  rows from appearing.
- Return to the existing outer console loop when the service finishes; do
  not change the shell's menu, other options, or closing behavior as part of
  this task.

No other task's rules are imported into this feature: this service filters
by the month component of each valid call date (the prompt has no year),
not by a user-specified year or reference date. It joins vessel names from
vessels data using vessel_id; it does not assume call_id or vessel_id is
encoded in a filename.

7. INTEGRATION POLICY RESOLUTION
================================================================

Use INTEGRATED-CONTRACT-PLAN.md for the shared project root, raw call-row
shape, diagnostics, and fatal loader-error behavior. For each Task 5 row,
parse the complete arrival_date first; an invalid date is the first
diagnostic and prevents a later vessel lookup for that row. For a valid
date, diagnose and skip an unknown vessel. Continue processing later rows.
Sort valid output by arrival date, then vessel name casefolded, then call_id
as a final deterministic tiebreaker. The final call_id key resolves only
otherwise equal specified keys and does not replace the required date/name
ordering.

After stripping surrounding whitespace, accept integer month text
representations accepted by int() (including a leading plus/zeroes); reject
non-integer and out-of-range inputs using the exact mandated error string
and repeat only the month prompt. These are project policies for lexical
input and deterministic ties; all exact assignment strings and the
date/name primary sort remain unchanged.

The resolved policies above are the implementation decisions; exact
diagnostic wording is not mandated by the PDF. Use the shared stable
diagnostic convention and report only the first failure per invalid row.
